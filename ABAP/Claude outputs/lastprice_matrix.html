PO Last Price Logic Map

Kolom Last Price di tiap driver cetak PO (SmartForm) memakai logika yang berbeda. Peta ini memetakan output type NAST → program driver → grup logika, lalu membedah langkah last-price tiap grup. Tujuan: menyamakan kolom Last Price di report ZMMI_PO_EMAIL dengan hasil cetak per tipe PO.

01Output type → Driver

Sumber: TNAPR (KAPPL='EF'). Output type diambil per PO dari NAST (OBJKY = EBELN). Deteksi praktis di report: LS_EKKO-EKORG (mis. LTTE=local, ITTE=import) atau BSART.

03Alur keputusan (flow)

Alur inti yang berlaku di driver *_PDF. Node merah = titik yang membuat hasil beda antar grup.

flowchart TD

(A,B +CPV/CPC/CPM)?}
  B -- ya, mtart ZRAW --> C[Ambil CHARG dari EKET]
  B -- tidak --> D[CHARG kosong]

+ filter A~BSART}

ORDER BY KNUMV,EBELP,BEDAT
filter BSART]
  E -- Grup B/C/D --> G[Pilih PO acuan:
KNUMV tertinggi]
  F --> H[WAERS = currency PO acuan
A: KONV / B,D: EKKO]
  G --> H
  H --> I[["Harga = EKPO-NETPR

  I --> J{WAERS acuan = WAERS PO?}
  J -- beda --> K[Konversi 2-hop via IDR
kurs SY-DATUM]
  J -- sama --> L[CURRENCY_AMOUNT_SAP_TO_DISPLAY]

ke BPRME PO acuan]

Catatan quirk (bukan bug yang diperbaiki): WAERS diambil dari PO acuan KNUMV tertinggi, sedangkan harga (NETPR) diambil dari PO acuan EBELN tertinggi — bisa dua PO berbeda. Kalau currency-nya beda, NETPR (mata uang X) dikali kurs mata uang Y → nilai bisa "meledak". Report harus meniru ini agar sama dengan cetak.

04Contoh nyata — PO 4518000081 (TTE Local, Grup C)

Material SRCBCO · WAERS PO = IDR · qty 4.200 KG

PO acuan KNUMV tertinggi = 4503000427 → WAERS = EUR PO acuan EBELN tertinggi = 4518000080 → NETPR = 324,32 kurs EUR→IDR (SY-DATUM, KURST M) = 20.573,2 Last Price = 324,32 × 20.573,2 = 6.672.300,22 ✓ cocok cetak PO

Jika salah pakai logic Z01 (simple, KBETR 150 EUR): 150 × 20.573,2 = 3.085.980 — inilah nilai lama yang tidak cocok cetak.
